# xAura

Веб-приложение для оценки аниме, создания интерактивных тир-листов, отслеживания вкусового профиля и соревновательных мини-игр (мультиплеерная аниме-настолка Dominion, сезонный драфт, квизы по скриншотам и опенингам).

---

## Архитектура проекта

Приложение разделено на три ключевых контура:

1. **SPA Фронтенд (React 18 + Vite):**
   - Клиентский роутинг на React Router v6.
   - Стилизация через Tailwind CSS в темной киберпанк/dossier эстетике (`#070905`, неоновый зеленый `#BBF351`, тонкие сетки, срезанные углы `cut-wrap`).
   - Drag & Drop для тир-листов на библиотеке `@dnd-kit`.
   - Графика и анимации: Framer Motion, Canvas Confetti.
   - Локальный датасет на 15 000+ аниме (`public/data/anime.json`), кэшируемый в клиентском `IndexedDB` для мгновенной работы без повторных сетевых запросов.
   - На экранах `< 768px` автоматически отключаются тяжелые Canvas-анимации фона (`AsciiAuraBg`) и рендерятся мобильные Bottom Sheet шторки вместо ховеров.

2. **БД и Авторизация (Supabase):**
   - Supabase Auth (Email / Password).
   - Таблицы PostgreSQL: профили пользователей (`profiles`), оценки с детализацией по 6 параметрам (`ratings`), сохраненные тир-листы (`tier_lists`), история баттлов (`battle_games`), результаты ежедневных челленджей (`daily_results`), система дружбы (`friendships`).
   - Supabase Storage: публичный бакет `avatars` для пользовательских аватарок с политиками RLS.

3. **Игровой сервер реального времени (`/server`):**
   - Node.js + Express + Socket.io.
   - Обслуживает мультиплеерные комнаты для **Dominion** (аниме-монополия) и **Draft** (сезонная фэнтези-лига).
   - Обрабатывает броски кубиков, покупки, прокачку ячеек, таймеры ходов, обмен между игроками и игровой чат комнат.

## Игровые режимы и механики

### 1. Каталог и 6-осевая система оценки
- **Каталог (`/catalog`):** Поиск по русскому и оригинальному названию, фильтрация по жанрам, годам и типу. Клик по карточке открывает детальную модалку с синопсисом, метаданными и быстрой оценкой (1–10).
- **Оценка (`/rate`):** Детальная оценка по 6 параметрам:
  1. *Рисовка*
  2. *Идея*
  3. *Реализация*
  4. *Персонажи*
  5. *Сюжет*
  6. *Эмоциональность*
- Средний балл рассчитывается на лету и отображается на анимированном круговом SVG-индикаторе (Gauge). Данные агрегируются в профиле в радарную диаграмму вкусов.

### 2. TierMaker (`/tiermaker`)
- Полноценный конструктор тир-листов на базе `@dnd-kit`.
- Поддерживает создание и переименование кастомных рядов, настройку hex-цветов тиров.
- Поддерживает импорт шаблонов по прямой ссылке с сайта `tiermaker.com` через прокси.
- Сохранение тир-листов в базу Supabase с генерацией уникальной ссылки для шаринга (`/tierlist/:listId`).

### 3. Доминион (`/dominion`)
- Мультиплеерная пошаговая аниме-настолка на сокетах (до 4 игроков).
- Игровое поле 11x11 (36 периметральных клеток):
  - Покупка и прокачка аниме-франшиз (уровни 1–3).
  - Сбор аренды с оппонентов, попавших на купленные клетки.
  - Клетки случайных событий, налоги, тюрьма и стартовый бонус.
  - Механика торговли имуществом и деньгами между игроками.
  - Внутриигровой чат комнаты.

### 4. Драфт сезона (`/draft`)
- Комнаты драфта в реальном времени.
- Игроки по очереди (Snake draft) набирают команды из 5 аниме текущего сезона.
- Баллы команды начисляются на основе рейтингов выбранных тайтлов.

### 5. Квизы и Челленджи
- **Битва рейтингов (`/battle`):** Генерация пар тайтлов с разницей рейтинга строго в диапазоне 1.5–2.0 балла (бинарный поиск по отсортированному пулу). Игрок должен угадать, у какого тайтла рейтинг выше.
- **Угадай OP/ED (`/anime-oped`):** 10 раундов случайных аудиотреков из базы `songs.json`. Ограничение времени, подсчет очков и персональный рекорд.
- **Угадай кадр (`/screenshot-quiz`):** Загрузка случайных кадров из Shikimori API. На первых раундах скриншот сильно размыт, с каждым раундом блюр уменьшается.
- **Челлендж дня (`/daily`):** Единый ежедневный сид для всех пользователей. Стрики побед, обратный отсчет до полуночи и сохранение рекорда в общий лидерборд.

## Установка и запуск

### Требования
- Node.js 18+
- Учетная запись Supabase (бесплатный проект)

### 1. Клонирование репозитория
```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd xaura-site
```

### 2. Установка зависимостей
Фронтенд:
```bash
npm install
```

Игровой сокет-сервер:
```bash
cd server
npm install
cd ..
```

### 3. Переменные окружения

Создайте файл `.env` в корне проекта:
```env
# Клиентский доступ к Supabase
VITE_SUPABASE_URL=https://<your-project>.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...

# URL игрового сервера Socket.io (для локальной разработки)
VITE_GAME_SERVER_URL=http://localhost:3001
```

*(Опционально)* Создайте `server/.env` для сокет-сервера:
```env
PORT=3001
CLIENT_URL=http://localhost:5173
```

### 4. Инициализация базы данных Supabase

В веб-консоли Supabase перейдите в **SQL Editor** и последовательно выполните скрипты:
1. `sql/avatars_friends.sql` — создание колонки аватара, публичного бакета `avatars` со storage-политиками и таблицы `friendships`.
2. `sql/daily_results.sql` — таблица результатов ежедневного челленджа с индексами.

*Таблицы `profiles`, `ratings`, `tier_lists`, `battle_games` создаются базовой схемой Supabase при первом обращении или через стандартные миграции.*

### 5. Запуск в режиме разработки

Запуск фронтенда (порт `5173`):
```bash
npm run dev
```

В отдельном терминале запустите игровой сервер (порт `3001`):
```bash
cd server
node index.js
```

Приложение доступно по адресу: `http://localhost:5173`.

## Скрипты сборки и утилиты

- `npm run build` — сборка фронтенда в директорию `dist/` с помощью Vite.
- `node scripts/optimize-anime-data.js` — удаляет из `public/data/anime.json` дубли полей изображений (`preview`, `x96`, `x48`), минифицируя файл до ~5.7 МБ.
- `node scripts/parse-shikimori.js` — парсер для скачивания свежих данных тайтлов и опенингов с API Shikimori.

## Деплой

- **Фронтенд:** Деплоится как статический SPA на Netlify, Vercel или Cloudflare Pages (Build command: `npm run build`, Publish directory: `dist`). Для роутинга настроены редиректы в `netlify.toml`.
- **Игровой сервер (`/server`):** Требует постоянного Node.js процесса для WebSockets. Легко разворачивается на Render.com (манифест `render.yaml` уже настроен), Railway или любом VPS с PM2/Docker.
